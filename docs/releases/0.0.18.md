N Launcher 0.0.18 adds support for Switch 2 titles whose NSO modules declare very large static `.bss` sections (over 1 GiB, such as Red Dead Redemption Nintendo Switch 2 Edition):

- **NSO preparation limit (`src/program.cpp`)**: Raised the `m.end` preparation ceiling from 1 GiB to 2 GiB so modules with >1 GiB static `.bss` are accepted, while still rejecting invalid or excessive (>2 GiB) layouts. Added synthetic unit tests in `tests/test_program.py`.
- **Large-BSS runtime allocation (`tools/runtime_patches.py`)**: Backported the `nx2-flow 0.2.6` large-BSS fixes (`whole.c` allocates module `.bss` from `nx2_big_alloc` with fallback to `aligned_alloc`; `game.c` accounts for `bss_need` in `nx2_game_room_end()`; `main.c` reserves a 1536 MiB initial loader stretch with `2 * host` headroom and trims unused memory back to the kernel before the game starts).

Update through `[R]` in N Launcher, return to hbmenu, and reopen the updated NRO. Game data, memory profiles and saves are preserved.
