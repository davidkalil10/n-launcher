N Launcher 0.0.16 fixes a frontend crash during game preparation and improves progress when concurrent file reads contend for loader locks.

- A delayed display-image release no longer aborts the frontend. The pending image stays untouched while the event/job loop continues; other acquisition errors shut down safely.
- Reviewed nx2-flow PR #44 backoff lets lower-priority threads finish file reads and decompression. The helper is pinned and credited; this is a targeted backport, not a full loader update.
- Single-file and split NUP support, existing caches, memory profiles and saves are preserved. No kaiHEN update or reactivation is required.

Console validation: Pokopia and Elliot launching recovered with the display fix. The combined 0.0.15 test build started Zelda: Ocarina of Time in about 30 seconds, with audio, and completed the cutscene and following loading screen using Split Fiction as host with Automatic memory. Zelda saving/loading has not been separately tested. Synthetic host tests and Switch 2 NRO/link-map checks cover the changed paths.

Update through R in the regular N Launcher or the 0.0.15 Sync Test. Diagnostic builds disable updates. After installation, return to hbmenu and open the updated application manually. Confirm 0.0.16 in the top corner before removing the separate diagnostic/test NROs. The updater replaces only the NRO from which it was started; use the regular n-launcher.nro to keep that file as your main copy. Keep the entire switch/n-launcher data directory, including .runtime, content, settings and saves.
